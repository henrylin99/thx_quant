# 扶摇 API 契约手册

沉淀自 quantitative_analysis 项目与 fuyao_demo 的实测经验。上游文档与实际行为有出入的地方，**以本手册（实测口径）为准**。

## 基本信息

| 项 | 值 |
|---|---|
| Base URL | `https://fuyao.aicubes.cn` |
| 认证 | 请求头 `X-api-key`，key 从环境变量 `FUYAO_API_KEY` 读取 |
| Key 申请 | https://fuyao.aicubes.cn |
| 客户端超时 | 30s |
| 节流 | 单请求间隔 0.12s（实测 200+ 连发未触发 4001 限频） |

## 响应信封

```json
{"code": 0, "message": "ok", "data": {…}}
```

`code != 0` 一律视为业务错误（HTTP 状态码可能是 200），错误码表见下文。

## ⚠️ 时间口径（最大的坑）

**所有 `*ms` 字段都是「北京时间零点」的 epoch ms，不是 UTC。**

- 按 UTC 解析会得到**前一天**的日期
- 客户端统一用 `beijing_ms_to_ymd()`（`tz=UTC+8`）解析；前端 `client.ts` 同口径
- 反向转换 `ymd_to_beijing_ms()` 同样锚定北京时间零点

## ⚠️ 字段双命名

实测返回值与官方文档的字段名不一致，取值时**两者都试**：

| 实测返回 | 官方文档写法 |
|---|---|
| `high_price` | `highest_price` |
| `low_price` | `lowest_price` |
| `prev_price` | `prev_close_price` |

## ⚠️ 文档 vs 实测：竞价 stage

官方文档写 `finallive`（拼写还错了），**实测合法值为 `live` / `final`**。

## 批量与窗口上限（各接口不一致）

| 场景 | 上限 |
|---|---|
| 快照批量 / 估值快照 | ≤ 100 只（`BATCH_LIMIT`） |
| 个股异动原因（按股票查询） | ≤ 50 只（`ANOMALY_BATCH_LIMIT`） |
| 财务报表 | ≤ 20 期 |
| 热股热度历史 | ≤ 1 年 |
| ETF 历史窗口 | ≤ 5 自然年 |

超限返回 `1003`。指数快照另有「未知代码整批连坐」问题（一个错代码 1002 导致整批失败）。

## 业务错误码全集

| code | 含义 | 教学提示 |
|---|---|---|
| 4001 | 请求过于频繁（限频） | 客户端已内置 0.12s 节流，连点请求可体验一次限频 |
| 1002 | 无效代码或非交易日 | 指数快照中未知代码会导致整批连坐 |
| 1003 | 超出批量/窗口上限 | 如批量 >100 只、热股历史超一年、ETF 历史窗口超 5 自然年 |
| 1004 | 参数组合非法 | 如热榜走势 start_date > end_date |
| 3001 | 标的不存在 | 基金接口 |
| 3002 | 数据未就绪 | 如当日异动原因暂不可用、场外基金走场内接口 |
| 3004 | 不支持的数据类型 | 如场外基金查询场内快照 |
| 5003 | 未披露报告期 | 财务接口，公司尚未披露该期报表 |

本地缺 key 时客户端抛 `FuyaoError("no_key")`（自定义码，非上游返回）。

## thscodes 格式

`600519.SH` / `000001.SZ` / `300750.SZ` / `688981.SH`——交易所后缀必须正确。
